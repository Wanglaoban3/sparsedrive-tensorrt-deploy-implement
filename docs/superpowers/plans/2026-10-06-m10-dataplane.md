## Review Focus

1. **wrap-lease 误杀 fence 在途读者**（GPU 读槽被覆写 = nvgpu fault 硬崩，项目头号坑）：活消费者持槽 hb 老度峰值 ≈ 2×svc + post 段 503ms 抖动（实测）≈ 690ms，默认 wrap lease 取 800ms（k=6 圈）在其上；FT 用无 CUDA 的 sp_sub 验证抢占路径，50ms 故意过小值只对 no-cuda 消费者注入。
2. **skip-lag 吞帧跨场景边界**：边界判定 `fm.scene != cur_scene` 只比较已处理帧，跳过边界帧后下一处理帧 scene 变化仍触发 tmat=identity/dt=0.5 复位——FT-M10-2 的 SIGSTOP 窗必须横跨 k=40 场景边界并断言 reset 日志行存在。
3. **弃帧的 parity 缓冲竞态**：弃帧检查点只能在设防段同步/提交**返回后**（返回即该段 GPU 工作完成，k+2 同 parity 覆写有 2 帧 ≈90ms 时序余量且被弃帧不再新增在飞工作）；不得在段中途强跳。
4. **watchdog 分级不能放走真 hang**：tier1 弃帧只救"卡后能返回"的停顿；tier2（dl + max(dl/2,500ms) 内主循环未 take 弃帧请求）必须仍 exit 13；`SP_WD_MS` 强制覆盖保持直退 13（逃生门不分级）。FT2 原语义（STALL→exit13）随之改为 HANG→exit13，STALL→abandon 继续。
5. **unit 变更与 env 交互**：`sp-modelnode@.service` ExecStart 变了要重装 + `daemon-reload`；`SP_BUS_WRAP_LEASE_MS` 进 `m3.env`（EnvironmentFile 每次 start 重读，改值只 restart）。
