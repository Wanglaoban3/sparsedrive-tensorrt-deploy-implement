# M9a sp_trigger 实施计划（L1 规则车载移植 + 规则插件 ABI）

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 sp_trigger——CPU 常驻进程，只读 sp_result_m3 信箱，跑可插拔 L1 规则（events.py 15 条的"现在时"车载移植），事件流落盘 + 配额仲裁；规则 = .so 插件（统一 C ABI）+ 阈值外置配置，不改 core 增删规则。

**Architecture:** 三个新文件组：①`sp_rule.h`（ABI 结构）+ `sp_ruleload.h`（header-only 加载器：扫目录 dlopen、ABI 校验拒载、THR 段注入、SIGHUP 重扫）②`sp_trigger.cpp`（宿主：10Hz tick 读信箱 seqlock → 按 seq join manifest 取 l2g → 差分 ego 运动学 → 组 FrameCtx（含 64 帧历史环）→ 逐规则 eval → 去重/配额 → jsonl 事件流；ctx-dump 模式落 FrameCtx 二进制作对拍夹具）③规则 .so ×14 + 模板 + thr.conf。关键链（node/引擎/插件/环）零改动。

**Tech Stack:** C++14 aarch64（板上 g++），header-only 库沿 sp_watch.h/sp_result.h 惯例；板测 runner 沿 `_m10_boardtest.py`；paramiko 驱动。

**Spec:** `docs/superpowers/specs/2026-10-06-m9-multimodel-dla-design.md`（§3 决策表、§4/§4.2 可插拔纪律、§7.5/§7.7 门禁、§8 M9a 行、§9 阈值重标定纪律）

## Global Constraints

- 板子系统冻结：JetPack 5.1 / CUDA 11.4 / TRT 8.6.1.2；不动板子环境；编译产物只落 `/usr/local/{bin,lib}`；/opt/m0 noexec。
- **关键链零改动**：sp_modelnode.cpp / sp_bus.* / 引擎 / DFA 插件 / m3 环布局一概不动；M9a 全部为新文件 + systemd 新单元。
- 信箱只读（`res::Mailbox::attach`），不碰图像环、零 GPU/DLA、零 CUDA context。
- 权限纪律（M-PROD D）：新单元 UMask=0027，事件流/状态目录 /var/lib/sp/trigger 0750，文件 0640。
- 模块级编译测试，不整引擎重编；BOARD_HOST/BOARD_PASS 只运行时注入。
- 事件纪律（ad-data-engine §5）：同 log ±5s 贪心去重、事件类型配额、全局预算 2-5%（5fps≈300 帧/min → 全局默认 ≤15 事件/min）。
- 阈值重标定纪律（spec §9）：thr.conf 默认值只是种子，门禁前必须跑 3min 稳态观察 → 分位数重标。
- 类别映射（nuScenes det label）：VEHICLE={0 car,1 truck,2 construction_vehicle,3 bus,4 trailer}，VRU={6 motorcycle,7 bicycle,8 pedestrian}，锥桶={9 traffic_cone}，屏障={5 barrier}——执行时以 eval_t6_mini_v8.py 的 class 列表实探核对。
- 时间窗一律按 ts 实际差值（秒），不用固定采样数（events.py 的 DT=0.1 假设在 5fps/30fps 下不成立）。

## Review Focus

1. **LATCH/旧帧不进规则**：信箱 status!=0（last_valid 重发）时 ctx.seq 重复/倒退 → 规则窗口被旧帧污染。期望：非 NOMINAL 帧跳过 eval、不推历史环。（Task 3 板测断言）
2. **场景边界 ego 运动学假尖峰**：l2g 跨场景跳变 → speed/acc/yaw_rate 一次巨大差分 → 假急刹/急转事件。期望：scene 变化时清历史环、当帧不差分。（Task 3 板测断言）
3. **信箱读竞争**：10Hz tick 撞上节点发布（seqlock 奇数/撕裂）。期望：read_latest 失败该 tick 跳过，永不自旋死、不崩。（Task 2 板测）
4. **坏插件不倒宿主**：垃圾文件/ABI 不匹配/缺符号 .so 在加载期被拒并记日志，宿主继续；规则 eval 内崩 = 进程死由 systemd 拉起（spec §6 允许），但加载期必须全防御。（Task 1 板测）
5. **事件流磁盘增长**：常驻 --loop 下 jsonl/ctx-dump 无界。期望：10MB×5 轮转（logrotate 纪律同 Phase D）。（Task 2 断言）

**Interfaces:**

- Produces:
  - env 契约（trigger.env）：`SP_TRIG_RING=m3 SP_TRIG_HZ=10 SP_TRIG_MANIFEST=/opt/m0/trt-dev/nv12_r0/manifest.jsonl SP_TRIG_RULES_DIR=/usr/local/share/sp/rules SP_TRIG_THR=/etc/sp/thr.conf SP_TRIG_OUT=/var/lib/sp/trigger SP_TRIG_CTX_DUMP=0`
  - tick 主循环（10Hz）：`read_latest` 失败/seq 未前进 → 跳过本 tick；status!=0 → 跳过不推环；scene 变化 → 清历史环；seq 前进 → manifest join（`mki=(seq-1)%nman`，镜像 sp_modelnode.cpp parse：只取 ts/scene/l2g）→ ego 差分（speed=|Δp|/Δt 沿 heading 中点投影、acc=gradient、yaw_rate=d(heading)/dt，跨帧 dt 用 ts 实差）→ ctx → 逐规则 eval → 事件写 `events.jsonl`（一行 `{"ts_ns":..,"seq":..,"event":..,"strength":..}`）

  - SIGTERM 优雅退出（关 jsonl flush）；SIGHUP → rule_rescan
- 本任务无规则重点：仅模板 demo_speed_high 驱动全链。
